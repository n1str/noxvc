# Архитектурные решения

Коротко о главных технических решениях: что выбрано, что рассматривалось и почему.
English: [../en/decisions/](../en/decisions/)

## 1. Один процесс на Rust (axum + tokio)
Один бинарник отдаёт REST API, WebSocket gateway, веб-клиент и обновления приложения. Отдельные сервисы — только
там, где готовый компонент явно лучше (LiveKit, PostgreSQL, S3).
*Рассматривали:* микросервисы, actix-web. *Почему:* небольшие установки и команда; лишние сервисы — только
эксплуатационная сложность.

## 2. Медиа: WebRTC через SFU LiveKit
Голос, камеры и экран идут через LiveKit (отдельный контейнер со встроенным TURN). Сервер проверяет права
(подключаться, говорить, транслировать) и выдаёт короткоживущие токены; кто в голосе — узнаёт из подписанных
вебхуков LiveKit. Opus с DTX/FEC/RED, adaptive stream и dynacast, simulcast для видео.
*Рассматривали:* PCM по WebSocket (блокировка головы очереди TCP — заикания), mesh WebRTC (не тянет больше 4–5
человек), SFU внутри Rust-процесса (месяцы работы: simulcast, оценка канала, TURN), mediasoup (библиотека — сигнализация
на нас). *Почему LiveKit:* готовый SFU (Apache-2.0) в одном контейнере, один UDP-порт, встроенный TURN, зрелые SDK,
в том числе на Rust (им пользуется приложение для нативного захвата экрана).

## 3. Веб-клиент: React + TypeScript + Vite, общий с приложением
Один бандл работает в браузере и в окне Tauri: `motion` (анимации), `@tanstack/react-virtual`, `lucide-react`,
`i18next` (ru/en), `livekit-client`, `zustand`.
*Рассматривали:* SolidJS, Svelte, чистый JS. *Почему:* зрелые библиотеки анимаций и виртуализации, компоненты LiveKit.

## 4. PostgreSQL и миграции sqlx
Пул соединений, версионные миграции, полнотекстовый поиск на `tsvector` (с русской морфологией).
*Рассматривали:* SQLite + FTS5 (один писатель, нет морфологии из коробки). *Почему:* конкурентная запись, нормальные
миграции и индексы, качество поиска.

## 5. Без Redis на одном узле
Присутствие, буфер RESUME для gateway, кэш прав и ограничения частоты — в памяти процесса за небольшими
интерфейсами. Общее хранилище понадобится только при нескольких процессах сервера.

## 6. Файлы — в S3 (по умолчанию Garage)
Вложения, аватары, баннеры, эмодзи и иконки серверов хранятся в любом S3-совместимом хранилище; в compose — Garage на
одном узле. Локальный диск тоже поддерживается (`RELAY_STORAGE=local`). Аватары и баннеры перекодируются фоновой
очередью (ffmpeg), поэтому как медиа профиля оригиналы никогда не отдаются.

## 7. Приложение: Tauri 2 (Windows)
Окно WebView2 загружает веб-клиент с сервера; нативное — на Rust: горячие клавиши через Raw Input (ничего не
перехватывается), нативный захват экрана (Windows Graphics Capture + Media Foundation H.264 в LiveKit Rust SDK),
определение игр, подписанные обновления (Ed25519).
*Рассматривали:* Electron (тяжелее, второй движок браузера в комплекте). *Почему:* маленький установщик, Rust для
нативного кода.

## 8. Права: одна функция, маска u64, порядок как в Discord
`perms.rs` считает права в одном месте: базовые роли (`@everyone` + роли), администратор, переопределения канала в
порядке Discord (`@everyone` → роли → участник), неявные зависимости (без VIEW_CHANNEL — ничего в канале). Иерархия
ролей проверяется отдельно (`can_manage`). Обе функции покрыты табличными тестами; все обработчики берут права только
отсюда.

## 9. Gateway: протокол в стиле Discord с RESUME
`/gateway` — от сервера к клиенту: HELLO → IDENTIFY/RESUME → READY/RESUMED → DISPATCH `{op, t, s, d}` с heartbeat.
Сеанс хранит последние 1000 событий 120 секунд после обрыва: короткий обрыв сети восстанавливается без потери событий.
Действия клиента — через REST.

## 10. Необязательная регистрация по приглашениям
По умолчанию регистрация открыта. В режиме `invite` аккаунт создаётся только по одноразовому коду: 24 символа без
похожих (около 119 бит), в базе — только SHA-256. Код расходуется в той же транзакции, что и создание пользователя
(`UPDATE … WHERE не использован, не отозван, не истёк RETURNING`), поэтому из параллельных попыток с одним кодом
проходит одна, а любая ошибка откатывается. Коды по одобренным запросам — HMAC от ключа сервера: автор видит ссылку,
пока она не использована, а сам код не хранится. Администраторы инстанса задаются только переменной окружения.
