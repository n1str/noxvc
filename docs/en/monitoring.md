# Monitoring

## With the compose profile

```sh
cd deploy && docker compose --profile monitoring up -d
```

Starts Prometheus, Grafana, `postgres-exporter` and `node-exporter`. Grafana listens on `GRAFANA_BIND`
(default `127.0.0.1:3000`), user `admin`, password `GRAFANA_ADMIN_PASSWORD`. Dashboards are provisioned into the
**NoxVC** folder:

- **NoxVC — Live Overview** — users online, voice, messages, HTTP rates and latency, DB pool, storage, LiveKit,
  invites, host CPU/memory/disk/network;
- **NoxVC — PostgreSQL** — connections, transactions, locks, tables, slow queries (`pg_stat_statements`);
- **Node Exporter Full**, **PostgreSQL (detail)** — adapted community dashboards.

Alert rules are in [`deploy/monitoring/prometheus/relay-alerts.yml`](../../deploy/monitoring/prometheus/relay-alerts.yml)
(backend down, 5xx rate, disk/memory, PostgreSQL health, voice connect failures and media loss). Prometheus evaluates
them; connect Alertmanager if you want notifications.

## With your own Prometheus

| Target | Address (inside the compose network) | Metrics |
|---|---|---|
| NoxVC server | `relay:9464` (`RELAY_METRICS_ADDR`) | `relay_*`: users, voice, gateway, HTTP, DB pool, storage, media queue, invites |
| LiveKit | `livekit:6789` | `livekit_*` |
| Garage | `garage:3903/metrics` | `garage_*` |
| PostgreSQL | via `postgres-exporter` | `pg_*` (+ queries in `deploy/monitoring/postgres-exporter/queries.yaml`) |

The metrics ports are not published to the host. To scrape from outside, publish them on a private address only.
Import the JSON files from `deploy/monitoring/grafana/dashboards/` into Grafana (datasource UID `relay-prometheus`, or
pick yours when importing). They are generated by `node deploy/monitoring/grafana/gen-dashboards.mjs`.

Metric names keep the internal `relay_` prefix.
